# C：五组交错调度——NM37 HLS 验证报告

## 结论

**功能仿真与综合完成；相对原始 baseline 达到周期和 LUT 门槛，但不是本轮最佳候选。** CSim 数学 22/22、工具 0 errors，CSynth 退出码为 0。两个 PV worker 均为 **II=16、9,965 周期**，对照提交 `4a6fe476` 为 II=25、12,401 周期；然而顶层 LUT 从 1,072,241 升至 **1,180,595**，DSP 从 352 升至 **360**。相同环境下，B 候选的 PV 循环为 4,961 周期、顶层 LUT 1,055,705、DSP 352，因此优先选择 B 继续验证。

本结论限定在 Vitis HLS CSim 和 CSynth。尚未运行 RTL CoSim、Vivado 实现、物理时序、bitstream 或 NM37 板测。

## 调度解释与限制

源代码把五组独立 feature 映射到五个 lane。HLS 依赖分析确实报告了 `pv_sum` 的距离 5 RAW 关系；但对 PV 循环的调度警告又报告 `pv_sum` 的距离 1 约束，因此实际 achieved II 为 16，未达到仅按五组间隔所期待的较低 II。动态 lane 选择和更多状态也使每个 PV worker 的 Multiplexer LUT 升到 27,794。距离 1 约束及资源上升是工具报告中的事实；其精确成因仍需查看更细的调度／绑定图，不能只凭源码断定单一门级路径。

本轮 620 次迭代包含最后一批无效 lane，相比对照的 496 次增加 25%。虽然 II 降低，总循环仍为 9,965 周期。RTL 实例清单显示两个 worker 各一个 `runPeArray`，未出现 A 的阵列复制；DSP 小幅增加 8 不应误写成 PE 阵列增加。

测试程序开头的 `self-test-nan`、`self-test-inf` 是异常值自检；正式日志之后给出 `[math-summary] 22/22`、`[PASS]` 及 `CSim done with 0 errors`。本轮关闭 1024 长序列用例、RTL CoSim 和 IP 导出。顶层动态最大 latency 不是固定长度的实际运行周期。LUT、时钟均为 HLS 估算，尚不能证明物理可布局性、布线时序或板级性能。
