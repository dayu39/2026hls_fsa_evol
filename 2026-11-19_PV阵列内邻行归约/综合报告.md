# PV 阵列内邻行归约：Vitis HLS 2024.2 综合报告

## 结论

本实验在 `4bc3ca3` 的 B 版本基础上，把 PV 的 16 个 key row 部分和移入一次共享 `runPeArray` 调用。Vitis HLS CSim 和 CSynth 均通过；PV 双 worker 的关键循环由 **4,961 周期、II=10、496 次迭代**改善为 **1,325 周期、II=5、256 次迭代**，局部周期降低 **73.3%**。

**整体性能与面积退步。** 顶层 `run` 最小延迟由 9,403 增至 11,647 周期（+23.9%），LUT 由 1,055,705 增至 1,177,179（+11.5%），FF 由 241,737 增至 511,645（+111.7%）。`runPeArray` 维持 II=5，但其调用延迟由 B 的 9 周期增至 49 周期；该共享模块也服务 QK 和 softmax 阶段。源码结构与上述数据支持“更深的共享 PE 流水拖慢其他阶段”的解释，但本次未做逐阶段 RTL 波形归因，不应把新增的全部 2,244 顶层周期精确归给某一个阶段。

## 核心结构变化

| 位置 | B 原版 | 本实验 |
| --- | --- | --- |
| `runPeArray` | 每行从外部 `operand_c[row][col]` 取 FP32 加数 | 增加默认关闭的 `pv_row_chain`；PV 模式下第 `row>0` 行从前一行 `result[row-1][col].out_accType` 取加数 |
| PV 控制循环 | `pv_row_sum[row+1][col]` 跨相邻 wave 保存部分和；每个 wave 发射不同 feature 的行 | 同一个 feature 的全部 key row 在单次 PE 调用内依次累加；只保存末行结果到 `pv_sum[context][col]` |
| 输出累加 | `alpha * output_acc + pv_sum` | 保持原调用与计算顺序 |

算法保持每列 `row=0..15` 的 FP32 FMA 累加次序。PV 外层不再有 `pv_row_sum` 的距离 1 反馈，Vitis 识别 `pv_sum` 的距离 8 RAW 依赖。这里的依赖是真实的结果缓存读写关系，没有把它谎报为无依赖。由于该模式加入共享 `runPeArray`，硬件要同时支持普通 PE 输入和邻行结果输入；局部缩短循环与模块面积增大同时发生。

## 正式综合结果

| 指标 | B `4bc3ca3` | 本次 `05cc702` | 变化 |
| --- | ---: | ---: | ---: |
| CSim 数学用例 | 22/22 | 22/22 | 一致 |
| CSim 工具错误 | 0 | 0 | 一致 |
| PV worker 0/1 关键循环 latency | 4,961 / 4,961 周期 | 1,325 / 1,325 周期 | 各减少 3,636，73.3% |
| PV 外层循环 II | 10 / 10 | 5 / 5 | 各减少 5 |
| PV 外层 trip count | 496 / 496 | 256 / 256 | 各减少 240 |
| `runPeArray` 调用 latency | 9 周期 | 49 周期 | 增加 40 |
| `runPeArray` 调用 II | 5 | 5 | 不变 |
| 顶层 `run` 最小 latency | 9,403 周期 | 11,647 周期 | 增加 2,244，23.9% |
| 顶层 LUT | 1,055,705 | 1,177,179 | 增加 121,474，11.5% |
| 顶层 FF | 241,737 | 511,645 | 增加 269,908，111.7% |
| 顶层 DSP / BRAM_18K | 352 / 8 | 352 / 8 | 不变 |
| 顶层估算时钟 | 7.300 ns | 7.300 ns | 不变 |

本次 PV 循环为 `VITIS_LOOP_365_33`；两个 worker 报告均显示 1,325 周期、II=5、trip count 256，并各含一个 `runPeArray` 子实例。B 的对应循环为 `VITIS_LOOP_373_33`，4,961 周期、II=10、trip count 496。顶层 DSP 仍为 352，与原 B 一致，未见 A 实验那样的 PE 阵列复制。新 `runPeArray` 单模块报告为 **128 DSP、200,131 FF、446,988 LUT**、49 周期、II=5；其 LUT 估算已超过单个 SLR 的 434,560 LUT，提示后续物理布局的跨 SLR 风险，不能据此断言它必然无法实现。

Vitis 目标 10.00 ns、时钟不确定度 2.70 ns、顶层估算 7.300 ns，恰好达到有效预算，没有正裕量。顶层 1,177,179 LUT 约占器件总量 1,303,680 的 **90.3%**，比 B 约 81.0% 更接近面积上限。FF、LUT 均为 HLS 估算，不是 Vivado 布局布线后的资源或物理时序。

## 判断与限制

本方案成功验证了一个结构假设：把真实的跨循环 PV 部分和反馈收进阵列函数，可显著降低该 PV 循环的 II 与周期。但共享 PE 的调用延迟和寄存器开销上升，抵消并超过 PV 局部收益。当前候选**不优于 B，暂不作为后续整体性能优化的起点**。可保留其依赖变换思路，下一轮如要继续，应设法让 PV 邻行通路不拉长 QK/softmax 共用 PE 的调用延迟，同时严格监控实例数与 LUT；把 PV 独立复制成第二套阵列有超过容量的风险。

本轮没有运行 RTL CoSim、IP 导出、Vivado 实现、板测或 1024 长序列 CSim。顶层 `run` 的动态最大延迟涉及不同输入路径，本文仅比较同口径最小延迟；不能把 HLS 数字称为固定长度的板上吞吐率。
