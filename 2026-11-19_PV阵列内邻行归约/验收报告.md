# PV 邻行归约实验验收报告

## 验收结论

**功能和 C 综合通过；相对 B 的整体性能验收未通过。** Vitis HLS CSim 数学测试 22/22、工具 0 errors，CSynth 完整结束。PV 双 worker 的循环由 4,961 降至 1,325 周期，但顶层 `run` 最小延迟由 9,403 升至 11,647 周期，LUT 由 1,055,705 升至 1,177,179，估算时钟仍为 7.300 ns 且无正裕量。

| 验收项 | 结果 |
| --- | --- |
| 源码起点 | B：`4bc3ca3fb11fb124107dba53707fce7343f17f51` |
| 实验源码 | `05cc7029bfe1a9fbe682b7b8fe14957d3c9506e4`；独立分支 `experiments/pv-neighbor-chain-20261119` |
| 本地功能 | WSL g++ 16×16/head128 原 testbench，22/22、`[PASS]` |
| 远端功能 | NM37 环境 Vitis HLS 2024.2 CSim，22/22、0 errors |
| C 综合 | 完整生成顶层、双 PV worker 和共享 PE 报告；脚本记录 `END=2026-11-19T17:54:32+08:00` |
| PV 局部效果 | 1,325 周期、II=5、256 次迭代；比 B 减少 73.3% 周期 |
| 顶层效果 | `run` 最小延迟 +23.9%；LUT +11.5%；FF +111.7%；DSP 和 BRAM 不变 |
| 范围 | CSim 和 CSynth；未做 RTL CoSim、IP 导出、Vivado 实现或板测 |

根因判断：PV 部分和在共享 PE 阵列内逐行传递，消除了 B 的跨循环距离 1 反馈，却把 `runPeArray` 调用延迟从 9 拉长至 49 周期，增加大量寄存器，并影响复用这一模块的其他阶段。此为源代码与 HLS 报告支持的解释，未做逐阶段 RTL 波形归因。详细数值和原始证据见[综合报告](./综合报告.md)。

**后续优化仍以原 B `4bc3ca3` 为性能起点。** 本分支保留为一次已验证的负结果和架构线索；本次不把它当作新的最佳实现。若继续探索邻行归约，优先寻找不拉长共享 PE 普通调用路径的实现，并先核查资源与物理时序。
