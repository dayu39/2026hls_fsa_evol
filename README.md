## 实验包

| 候选 | 独立目录 | 只改变的设计源码 | 待验证假设 | 主要风险 |
| --- | --- | --- | --- | --- |
| A：分离累加阶段 | `2026-11-18_PV分离累加阶段/` | `src/stream/split_d/split_d_controller.cpp` | 把 PE wave 和输出累加分成两个循环，让输出累加不受 PE 反馈 II 约束 | 循环启动开销或模块复制抵消收益 |

## 已完成的本地验证

每个候选均已使用 WSL Ubuntu 24.04、g++ 13.3 和本机 Vitis 2024.2 头文件，编译原有完整 `test_fsa_stream_split_d.cpp` 测试程序。配置为 16×16 PE、head128；三个候选分别得到数学检查 `22/22` 和 `[PASS]`。各目录中的 `build/local_split_d_check/` 保留日志。复查命令：

```powershell
cd <候选目录>
.\validate_local.ps1
```

这一步仅验证 C++ 功能。2026-11-18 至 19 日又在 NM37 上完成了三个候选各自独立的官方 Vitis HLS CSim/CSynth，结果见下表。

三个候选均为 CSim 数学 22/22、工具 0 errors、CSynth 退出码 0。Vitis HLS 2024.2 Build 5238294，16×16 PE、head128，目标器件 `xcvu37p_CIV-fsvh2892-2-e`，目标时钟 10.00 ns、不确定度 2.70 ns。数字均来自本轮新构建，并保留在各实验的报告与证据目录。

A 的循环结构与其他版本不同：9,600 是完整 PV 外层组循环，而 25 是其内部 PE wave 循环的 II；不能把单组 wave 的 576 周期当作完整 PV 周期。B、C 与对照在完整 PV 阶段的指标可比较，但 C 的 trip count 从 496 增到 620。四组顶层估算时钟均为 7.300 ns，恰等于 `10.0−2.7` ns 的有效预算；这不是物理时序通过的证明。

原始 baseline `ebe529b` 的同级 PV 循环门槛为 10,886 周期，LUT 门槛为 1,213,113。B 与 C 在 HLS 估算下同时低于这两个门槛；A 虽降低周期，却因 PE 阵列复制使 LUT 超出器件总量 1,303,680。B 在已测的 PV 周期、LUT 和 DSP 上均优于 C，因此后续优先对 B 做 RTL CoSim 与 Vivado 实现检查。

## 复现方式

将三个目录分别放在 NM37 的独立路径。每个候选目录执行：

```bash
bash ./validate_candidate.sh
```

脚本会加载 `/opt/Xilinx_2024.2/Vitis/2024.2/settings64.sh`，固定 16×16 PE、head128，运行原仓库 `run_hls.sh` 的官方 CSim 与 CSynth，并关闭 CoSim、IP 导出和 1024 长序列用例。完整输出写入各自的 `logs/validation.log`；发现已有 HLS 构建目录时会停止，避免覆盖首次结果。不要把三个候选的源码叠加，也不要共用构建目录。

本轮在 NM37 上从实验提交 `4bc3ca3` 克隆代码，将三个候选并行放在互不干扰的构建目录运行。根目录的 `run_all_candidates.sh` 保存每个脚本的退出码和时间。每个实验目录内的 `验证报告.md` 及 `evidence/` 含完整日志、顶层报告、两个 PV worker 报告和 RTL 实例清单。正式流程未包含 1024 长序列、RTL CoSim、IP 导出、Vivado 实现或板测。
